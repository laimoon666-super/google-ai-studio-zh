## 1. 项目架构与核心机制

本插件专为 `https://aistudio.google.com/*` 深度定制，基于 Google Chrome Manifest V3 规范构建。

### 1.1 核心设计理念
- **确定性查表**：摒弃传统“AI 实时机器翻译”方案的高延迟、随机翻译、消耗 Token 等缺陷，采用预先勘察、人工核对的高质量“词典精确匹配 + 动态正则模板”策略。
- **严格安全边界**：绝对只翻译 Google AI Studio 的 UI 操作控件、表单标签、提示引导等界面元素；**绝不翻译**用户的 Prompt 原文、AI 模型的流式回复、以及嵌入的各类代码块（Code Blocks）。
- **零外部依赖**：全插件无 Node 编译时打包工具、无任何 CDN 外部脚本请求，纯原生 JavaScript / CSS，极高加载速度与本地离线可用性。

### 1.2 目录与模块分工

## 2. 新文案勘察与数据采集 (Recon SOP)

当 Google AI Studio 迭代升级或上线新特性（如 Gemini 新功能卡片）时，按以下标准化流程进行文案侦察。

### 2.1 勘察准则
- **只读操作**：在真实浏览器中操作勘察时，允许展开折叠、点击切换菜单、打开设置弹窗；**禁止**新建应用保存、删除数据、发送消耗配额的生图或复杂推理 Prompt。
- **环境隔离**：在独立 Chrome 标签页中进行操作，确保已配置英文环境，避免其他翻译类插件影响 DOM 原文。

### 2.2 推荐勘察执行脚本
在目标页面按下 `F12` 打开开发者工具 Console，或通过自动化工具直接执行以下精简探测代码：

```javascript
(() => {
  const vis = el => {
    const r = el.getBoundingClientRect();
    const cs = getComputedStyle(el);
    return r.width > 0 && r.height > 0 && cs.visibility !== 'hidden' && cs.display !== 'none';
  };
  
  const texts = new Set();
  const attrs = [];
  
  // 1. 抓取可见文本节点
  const walker = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT);
  let node;
  while ((node = walker.nextNode())) {
    const raw = node.textContent.replace(/\s+/g, ' ').trim();
    // 过滤单字符、数字及 Material Icons 连字符
    if (raw.length > 1 && node.parentElement && vis(node.parentElement)) {
      if (!node.parentElement.classList.contains('material-symbols-outlined') &&
          !node.parentElement.classList.contains('google-symbols')) {
        texts.add(raw);
      }
    }
  }
  
  // 2. 抓取交互属性 (placeholder, aria-label, title, alt)
  document.querySelectorAll('[aria-label],[placeholder],[title],[alt]').forEach(el => {
    for (const attr of ['aria-label', 'placeholder', 'title', 'alt']) {
      const val = el.getAttribute(attr);
      if (val && val.trim().length > 1) {
        attrs.push({ attr, val: val.trim(), tag: el.tagName.toLowerCase() });
      }
    }
  });

  const report = {
    url: location.href,
    collectedAt: new Date().toISOString(),
    textCount: texts.size,
    texts: [...texts].sort(),
    attrCount: attrs.length,
    attrs
  };
  
  console.log(report);
  return JSON.stringify(report);
})();
```

### 2.3 产物保存
将返回的 JSON 保存至 `recon/<模块名>.dump.json`，供词典录入比对与 Git 历史复核。

## 3. 词典开发与分卷维护规范

### 3.1 词典加载规范
所有词典脚本由 `manifest.json` 在 `content_scripts` 中按顺序同步加载，必须遵循 IIFE 立即执行函数规范，挂载至全局对象 `window.__AIZ_DICT__`：

```javascript
/* 分卷：Playground（对话实验室 / 运行设置） */
(function () {
  const D = (window.__AIZ_DICT__ = window.__AIZ_DICT__ || {});
  Object.assign(D, {
    "Run settings": "运行设置",
    "System instructions": "系统指令",
    "Temperature": "温度"
  });
})();
```

### 3.2 词条书写铁律
1. **Key 严格归一化**：
   - Key 必须为页面提取的真实英文原文。
   - 去除首尾空白，内部连续空格折叠为单一半角空格。
   - 大小写严格与页面一致。引擎虽有降级兜底，但词典必须写精确。
2. **禁止重复覆盖**：
   - 保持各分卷分工清晰，通用词写在 `_common.js`，专有词写在对应分卷，避免重复 key 相互覆盖。
3. **禁止收录项**：
   - 严禁收录品牌词（Google, Gemini, Imagen, Veo）、模型版本名（gemini-2.5-pro）、纯数字、纯符号。
   - 严禁收录 Material Icons 连字（如 `arrow_drop_down`, `more_vert`）。
4. **统一术语**：
   - 必须先查阅 `docs/术语表.md`，使用官方推荐译法，严禁自行杜撰别名。

## 4. 动态正则规则编写 (patterns.js)

静态词典无法覆盖包含动态变量的文案（例如：“Showing 15 of 200 items”、“Updated 5 minutes ago”、“Tokens: 1,024”）。此类文案通过 `src/core/patterns.js` 统一接管。

### 4.1 正则规则结构定义
```javascript
window.__AIZ_PATTERNS__ = [
  {
    name: "token_count",
    // 匹配如: 1,234 tokens / 12 tokens
    regex: /^([\d,]+)\s+tokens?$/i,
    replace: "$1 个 Token"
  },
  {
    name: "updated_ago",
    // 匹配如: Updated 5 mins ago / Updated 2 hours ago
    regex: /^Updated\s+(\d+)\s+(min|mins|minute|minutes|hour|hours|day|days)\s+ago$/i,
    transform: (match, num, unit) => {
      const unitMap = {
        min: "分钟", mins: "分钟", minute: "分钟", minutes: "分钟",
        hour: "小时", hours: "小时",
        day: "天", days: "天"
      };
      return `更新于 ${num} ${unitMap[unit.toLowerCase()] || unit}前`;
    }
  }
];
```

### 4.2 正则编写注意事项
- **锚定边界**：尽可能使用 `^` 与 `$` 进行完整匹配，严禁书写贪婪的无边界正则，防止误伤含有变量的上下文段落。
- **性能红线**：每个文本节点都会流经正则匹配链，正则复杂度必须为 O(N)，严禁嵌套回溯（ReDoS 隐患）。
- **参数安全**：在 `transform` 函数中处理捕获组时，必须做好空指针与未知参数的兜底防御。

## 5. 前端核心五大经典坑与防护方案

在 Google AI Studio 这类现代企业级 Angular / Polymer 单页应用（SPA）中进行 DOM 翻译，极易踩坑。以下是必须牢记的防护原则：

### 坑 1: Material Symbols 连字（Ligatures）被破坏
- **现象**：Google 界面大量使用 Material Symbols 图标字体，其实现原理是将文本 `menu`、`check_circle` 渲染为图标图形。如果引擎将 `menu` 汉化为“菜单”，图标会立即崩溃变成中文字符！
- **防御策略**：
  1. 引擎在遍历前检测父级元素 class：包含 `material-symbols-outlined`、`google-symbols`、`material-icons` 或 `ms-icon` 的节点直接跳过；同时对"单个小写单词"额外做一次 `getComputedStyle().fontFamily` 检测，命中 `Google Symbols` / `Material Icons` / `Material Symbols` 也一律跳过（防止新版本去掉 `notranslate` 类）。
  2. 词典白名单拦截：严禁在任何词典中加入包含下划线连字的纯小写图标名。

### 坑 2: `.notranslate` 与安全区域
- **现象**：AI Studio 自身给图标和部分组件加了 `notranslate` 类；如果引擎忽略它，会误伤图标；反过来，如果引擎自己给 `<html>` 加 `notranslate` / `translate="no"`，又会被自己的跳过规则命中，导致整页不翻译。
- **防御策略**：
  - 引擎把所有 `.notranslate`、`[translate="no"]` 元素视为保护区，直接跳过。
  - **绝对不要**给 `<html>` / `<body>` 添加 `notranslate` 或 `translate="no"`；扩展只设置自己的 `data-aiz-*` 属性。
  - 译文高亮只使用 `background-image` 渐变 + `border-radius`，不修改 `box-sizing`、`display`、`margin`，避免原 UI 布局抖动。

### 3. Angular 脏检查与 MutationObserver 死循环
- **现象**：Angular 框架绑定了大量局部数据模型，当扩展替换 `node.textContent` 时，会触发 DOM 变动事件；如果 MutationObserver 再次监听到该事件并重复翻译，将导致 CPU 100% 死循环与页面冻结。
- **防御策略**：
  1. **双集合幂等**：`processed`（已翻译节点）与 `seen`（已检查但未命中节点）两个集合保证每个文本节点最多处理一次；`applied` WeakMap 记录"自己写进去的译文"，在 observer 回调里先比对，值相同说明是自身写入，直接忽略。
  2. **只替换文本节点**：绝不重建 DOM、不改 `innerHTML`，只写 `node.nodeValue`，把对 Angular 的干扰降到最低。
  3. **节流队列**：DOM 变动统一进队列，`setTimeout(24ms)` 后按「每轮最多 400 个节点 / 10ms 时间片」增量处理，剩余留到下一轮，避免长任务卡顿。
  4. **跳过的子树上不挂观察器**：避免在代码编辑器、聊天容器等区域产生无意义的回调。

### 坑 4: 保护用户 Prompt、模型输出与代码块
- **现象**：若不加隔离，用户正在输入的 Prompt、模型推理生成的文字或 Python 示例会被篡改，导致业务功能严重受损。
- **防御策略**：
  - 核心引擎维护严格的**跳过选择器黑名单（Skip Selectors）**：
    - `[contenteditable]:not([contenteditable="false"])`、`[role="textbox"]`（所有用户输入框）
    - `pre`, `code`, `kbd`, `samp`, `.hljs`, `.monaco-editor`, `.cm-editor`（代码区域）
    - `ms-chat-turn`, `ms-user-query`, `ms-model-response`, `.markdown-body`（聊天记录与模型输出）
    - 注意：AI Studio 的 `ms-prompt-renderer` 是**整个主区域**的包裹元素，绝不能加入跳过列表，否则整页都不翻译。

### 坑 5: Shadow DOM 封装边界
- **现象**：部分 Google Web Components（如自定义按钮、滑块、对话框组件）内部使用 Shadow Root，常规 `document.querySelectorAll` 无法触达内部文本。
- **防御策略**：
  - TreeWalker 默认仅在主 DOM 树生效。对于核心组件的 Shadow Root，引擎在遍历元素时检测 `el.shadowRoot`，通过递归注册微观察器的方式穿透汉化，同时保持只读性。

## 6. 工具链与本地脚本使用指南

### 6.1 图标生成脚本 (`scripts/gen-icons.py`)
使用 Python Pillow 自动化生成全套高精圆角渐变图标。
- **依赖**：Python 3.10+，Pillow (`pip install pillow`)
- **执行命令**：
  ```bash
  python scripts/gen-icons.py
  ```
- **输出产物**：
  - `icons/icon16.png` (16x16 px)
  - `icons/icon32.png` (32x32 px)
  - `icons/icon48.png` (48x48 px)
  - `icons/icon128.png` (128x128 px)
- **特性**：内置 512px 母版渲染、4x Lanczos 抗锯齿下采样、系统字体（微软雅黑粗体）自动探测与几何兜底。

### 6.2 扩展打包脚本 (`scripts/pack.ps1` / `scripts/pack.py`)
- **推荐**：`python scripts/pack.py`（跨平台，zip 内路径统一使用 `/`，macOS/Linux 解压不会出现文件名带反斜杠）
- Windows 也可以用 PowerShell 版本把扩展生产文件打包为 ZIP 包：
- **执行命令**：
  ```powershell
  # 默认读取 manifest.json 中的版本号
  powershell -ExecutionPolicy Bypass -File scripts/pack.ps1

  # 或指定自定义版本号
  powershell -ExecutionPolicy Bypass -File scripts/pack.ps1 -CustomVersion "1.0.1"
  ```
- **过滤机制**：
  - 自动包含：`manifest.json`、`src/`、`icons/`、`README.md` 等生产运行所需资源。
  - 严格排除：`dist/`、`recon/`、`docs/`、`scripts/`、`fixtures/`、`CONTRACT.md`、`.git/`、`node_modules/`、`*.log` 等开发与勘察冗余文件。
- **输出产物**：`dist/google-ai-studio-zh-<version>.zip`，并在控制台实时打印文件尺寸与内部清单。

## 7. 版本发布流程与质检清单

发布新版本扩展前，请严格执行以下六步 SOP：

```
[步骤 1: 代码静态检查] ──> [步骤 2: 词条规范审核] ──> [步骤 3: 浏览器真机回归]
                                                            │
[步骤 6: 归档与发布]   <── [步骤 5: 执行 pack 打包] <── [步骤 4: 更新 manifest 版本]
```

### 详细核验清单
1. **静态语法检查**：
   ```bash
   node --check src/background.js
   node --check src/core/engine.js
   node --check src/core/patterns.js
   node --check src/core/boot.js
   node --check src/dict/_common.js
   node --check src/dict/playground.js
   node --check src/dict/build.js
   node --check src/dict/manage.js
   node --check src/popup/popup.js
   node --check src/options/options.js
   ```
2. **术语对齐**：核对新增词条是否已收录在 `docs/术语表.md` 中。
3. **真机加载回归**：
   - 在 Chrome 打开 `chrome://extensions`，点击“加载已解压的扩展程序”，选择本插件目录。
   - 打开 `https://aistudio.google.com/`，测试页面汉化、Popup 开关、设置页持久化。
   - 重点验证：输入 Prompt 是否正常、模型代码块是否完好无损、Material Icons 是否显示正常。
4. **版本同步**：确保 `manifest.json` 与 `README.md` 中的版本号严格保持一致。
5. **执行打包**：运行 `scripts/pack.ps1`，确认 `dist/` 下生成的 zip 大小正常且无越界文件。
6. **发布上线**：将 zip 包上传至 Chrome Web Store 开发者后台或 GitHub Releases。
